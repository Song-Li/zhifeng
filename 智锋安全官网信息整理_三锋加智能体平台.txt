## 4. 总体产品体系

### 4.1 当前产品结构

智锋安全当前不以“六锋”作为官网主线，而以“三锋闭环 + 零信任智能体防护平台”作为对外产品结构。

四个核心方向：

1. 洞锋：漏洞挖掘 / 风险发现
2. 渗锋：攻击验证 / 自动化渗透
3. 御锋：自适应防御 / 安全大脑
4. 零信任智能体防护平台：Agent、MCP 与工具调用安全治理

### 4.2 总体产品体系一句话

三锋闭环解决企业软件与系统的未知风险发现、真实攻击验证和持续自适应防御；零信任智能体防护平台解决 AI Agent 进入企业后的工具调用、数据访问、权限控制与自动执行安全。

### 4.3 产品体系图建议

页面可以设计为“四象限 + 中央 AI 安全基础设施”：

中央：

AI 原生安全基础设施 / 企业内部 AI 安全专家

左上：洞锋

找风险：漏洞挖掘、代码审计、MCP/Agent Tool 风险发现、增量代码检查

右上：渗锋

验风险：自动化渗透、攻击链验证、登录态测试、证据链报告

左下：御锋

防风险：安全大脑、自适应策略、自动阻断、联动处置、持续进化

管 Agent：工具调用控制、权限约束、数据访问审计、高风险操作阻断

底部闭环：

发现风险 → 验证风险 → 生成防御 → 持续进化 → 智能体安全控制

## 8. 第四产品线：零信任智能体防护平台

### 8.1 为什么需要这个产品

AI Agent 正在从“回答问题的助手”变成“可以调用工具、访问数据、连接系统、自动执行操作”的新型数字主体。企业引入智能体后，安全边界不再只是网站、代码和服务器，还包括 Agent 的上下文、工具调用、MCP Server、插件、权限、数据访问和自动执行链路。

现代智能体常见问题包括：

- Prompt 注入诱导 Agent 执行危险操作
- MCP Server 或 Tool 描述被投毒
- 工具权限过宽导致越权调用
- Agent 自动访问或外传敏感数据
- 多智能体协作时责任链不清
- 自动执行缺少审批、回滚和审计
- 外部工具和内部系统之间缺少隔离
- Agent 行为过程不可见、不可解释、不可追溯
- 企业无法统一管理不同模型、Agent、工具和插件的访问策略

因此，企业需要一个面向 Agent 运行过程的零信任安全控制层。它不是简单检测一个漏洞，而是对 Agent 的每一次感知、决策、工具调用、数据访问和自动执行进行持续验证、最小授权、行为审计和风险阻断。

### 8.2 产品定位

面向 AI Agent、MCP 与工具调用的新一代安全控制层

### 8.3 一句话介绍

零信任智能体防护平台为企业 AI Agent 建立工具调用、权限控制、数据访问、上下文风险检测和行为审计能力，让每一次智能体操作都可验证、可控制、可追溯、可阻断。

候选 C：

候选 D：

候选 E：

推荐标题：

零信任智能体防护平台：为企业 AI Agent 建立安全控制层

### 8.5 核心能力

#### 8.5.1 身份与权限控制

- Agent 身份管理
- 用户、Agent、工具、系统之间的访问关系建模
- 最小权限策略
- 分级授权
- 高风险操作二次确认
- 按任务、上下文、数据类型动态授权

#### 8.5.2 工具调用安全

- 工具调用前风险判断
- Tool / MCP Server 描述可信校验
- 危险工具调用识别
- 工具调用参数检查
- 工具调用白名单、黑名单和条件策略
- 工具调用链路审计
- 高危工具调用阻断或转人工审批

#### 8.5.3 Prompt 注入与上下文攻击防护

- Prompt 注入检测
- 间接 Prompt 注入检测
- 外部文档、网页、邮件、知识库中的恶意指令识别
- 上下文污染检测
- 系统指令和用户指令边界保护
- Agent 任务目标一致性检查

#### 8.5.4 数据访问与敏感信息保护

- 敏感数据识别
- 数据访问策略控制
- 数据脱敏与隐藏
- 防止 Agent 将敏感数据带出企业环境
- 外部模型调用前数据风险检查
- 数据使用审计

#### 8.5.5 行为监控与审计

- Agent 操作链路记录
- 工具调用日志

### 8.8 与三锋的关系

三锋解决企业软件与系统的攻防闭环：
